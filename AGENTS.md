# Repository Guidelines

## Code quality

- Write clean, human-readable code. Prefer clear names, simple control flow, and focused functions over clever or unnecessarily complex implementations.
- Follow the conventions already established in the relevant app or package.
- Preserve literal types for fixed TypeScript values instead of widening them to broad types. For example, declare string constant lists as readonly tuples (`const statuses = ["ready", "failed"] as const`), not `string[]`, and derive unions with `typeof statuses[number]`. Use `satisfies` when validating a shape without discarding precise inferred types.
- Never run checks manually (including lint, formatting, typechecking, builds, and tests). They run automatically when you finish a turn.

## Testing

- Do not write or add tests unless the user explicitly tells you what to test.
- When tests are requested, verify the specified observable behavior or meaningful contract; do not test tautologies.

## Project layout

- This is a pnpm monorepo. Apps live in `apps/*`; shared packages belong in `packages/*`.
- The minimal Expo React Native app is `apps/mobile` (`@apprelay/mobile`). It uses strict TypeScript; `App.tsx` is the root component and `index.ts` registers it with Expo.
- The Rust server is `apps/server` (`@apprelay/server`). Run it with `pnpm server`; it currently waits for Ctrl+C without opening network listeners. Keep it minimal until features are requested.
- Shared code-quality tools and Git hooks live at the repository root. Each app or package defines its own lint and typecheck scripts; root scripts run them recursively.
- Use `pnpm --filter @apprelay/mobile exec expo install` when adding Expo or React Native dependencies to keep versions SDK-compatible.
- Native `ios/` and `android/` directories are generated by Expo; configure native behavior through `apps/mobile/app.json` rather than editing generated files.
- Add matching checks to `.pi/pi-hooks.json` when adding apps or packages.
- Formatting runs on staged files through Husky and lint-staged (oxfmt for supported text files, rustfmt for Rust). Pi runs lint and typecheck through `.pi/pi-hooks.json`, including Clippy and `cargo check` for the server.
