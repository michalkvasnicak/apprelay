# R2 bucket setup

Use these settings when configuring a bucket for your own AppRelay deployment.

1. Create a dedicated R2 bucket using **Standard** storage.
2. Disable public `r2.dev` access and do not attach a public custom domain.
3. Create R2 S3 API credentials with **Object Read & Write** permission,
   restricted to this bucket.
4. Configure retention to match `APPRELAY_IPA_LIFETIME_DAYS`:
   - **Unset:** do not configure an expiration rule for `originals/permanent/`.
   - **Set to N days:** enable a lifecycle rule for `originals/retained-Nd/`
     deleting objects **N days after creation**. For example, a value of `7`
     requires a rule for `originals/retained-7d/`.
   - Do not apply expiration rules to the whole bucket or the `originals/`
     prefix; those would also delete indefinitely retained IPAs.
   - When changing the lifetime, keep rules for previous retention prefixes
     until their objects have expired. Changing server configuration does not
     update existing upload deadlines.
5. Configure incomplete multipart uploads to abort after **1 day**.
6. Configure CORS with your deployment's exact web origin, replacing the example
   below:

```json
[
  {
    "AllowedOrigins": ["https://apprelay.example.com"],
    "AllowedMethods": ["PUT", "GET", "HEAD"],
    "AllowedHeaders": ["*"],
    "ExposeHeaders": ["ETag"],
    "MaxAgeSeconds": 3600
  }
]
```

R2 lifecycle deletion is asynchronous. Configure finite-retention rules explicitly;
the server does not create them. Remove any previously configured bucket-wide or
`originals/` expiration rules before using indefinite retention.

Set the server environment variables listed under
[R2 upload configuration](README.md#r2-upload-configuration).
